# رفع الـ API على دومين فرعي ومجلد داخل `public_html`

دليل مبسّط لمشروع **Mindlytics** (Laravel). مسارات الـ API في الكود تبدأ بـ:

`/api/v1/...`  

**إن كان الموقع مرفوعًا على الدومين الرئيسي** (مثل `https://mindlytics-academy.com`) فلا حاجة لدومين فرعي: اختبر `https://mindlytics-academy.com/api/v1/health`.

مثال إن استخدمت دومينًا فرعيًا للـ API فقط: `https://api.اسم-نطاقك.com/api/v1/health`

---

## 1) الفكرة المهمة (اقرأها مرة)

Laravel لا يُعرَض من جذر المشروع كله، بل من مجلد **`public`** فقط (ملف `index.php` بداخله).

- إذا جعلت الدومين الفرعي يفتح مجلدًا خاطئًا (مثل جذر المشروع بدون `public`) ستحصل على **404** أو **500** أو قائمة ملفات غير آمنة.
- الحل: في لوحة الاستضافة (cPanel أو غيرها)، **Document Root** للدومين الفرعي يجب أن يكون على الشكل:
  - `public_html/اسم-مجلد-api/public`  
  وليس `public_html/اسم-مجلد-api` فقط.

---

## 2) ماذا ترفع في المجلد؟

انسخ **مجلد المشروع كاملًا** (مثل مجلد `Mindlytics` من جهازك) إلى المجلد الذي أنشأته، مثلاً:

`public_html/api/`  

بحيث يصبح لديك مثلًا:

- `public_html/api/app/`
- `public_html/api/bootstrap/`
- `public_html/api/config/`
- `public_html/api/public/`  ← هذا هو الذي يجب أن يشير إليه الدومين الفرعي
- `public_html/api/.env` (تنشئه على السيرفر، لا ترفع `.env` من جهازك إن كان فيه أسرار)

---

## 3) إعداد الدومين الفرعي في الاستضافة

1. أنشئ الدومين الفرعي (مثل `api.yourdomain.com`).
2. اربط **Document Root** أو **مجلد الجذر** للدومين الفرعي بمسار **`.../public`** كما في القسم 1.
3. فعّل **HTTPS** (شهادة Let’s Encrypt عادةً من نفس اللوحة).

---

## 4) ملف `.env` على السيرفر — ماذا تغيّر؟

أنشئ `.env` من `.env.example` (أو انسخه من نسخة عمل محلية ثم عدّل القيم الحساسة).

| المتغير | ماذا تضع؟ |
|--------|-----------|
| `APP_URL` | عنوان الدومين الفرعي بالكامل، مثل `https://api.yourdomain.com` (بدون شرطة في النهاية عادةً مقبول في Laravel) |
| `APP_ENV` | `production` |
| `APP_DEBUG` | `false` (مهم للأمان والأداء) |
| `APP_KEY` | نفّذ مرة واحدة: `php artisan key:generate` إذا كان فارغًا |
| قاعدة البيانات | نفس إعدادات الموقع الرئيسي إذا كان الـ API والموقع **نفس التطبيق ونفس البيانات**؛ أو قاعدة منفصلة إذا قررت فصلها لاحقًا |
| `SESSION_DOMAIN` | غالبًا اتركه `null` أو اتبع توثيق الاستضافة؛ للدومين الفرعي فقط قد تحتاج قيمة مثل `.yourdomain.com` إذا استخدمت جلسات عبر نطاقات متعددة |
| تخزين الملفات (R2 وغيره) | انسخ نفس القيم التي تعمل على الموقع الرئيسي إذا كان نفس التطبيق |

بعد أي تعديل على `.env`:

```bash
php artisan config:clear
php artisan config:cache
```

(نفّذها من SSH داخل مجلد المشروع على السيرفر إن وُجد SSH.)

---

## 5) أوامر شائعة بعد الرفع (SSH)

من مجلد المشروع (مثل `public_html/api`):

```bash
composer install --no-dev --optimize-autoloader
php artisan migrate --force
php artisan storage:link
php artisan config:cache
php artisan route:cache
```

إن لم يكن SSH متاحًا: استخدم **Terminal** في cPanel إن وُجد، أو رفع `vendor` جاهزًا من بيئة مطابقة لإصدار PHP (أقل تفضيلًا لكنه يحدث على بعض الاستضافات).

---

## 6) صلاحيات المجلدات

تأكد أن السيرفر يستطيع الكتابة في:

- `storage/`
- `bootstrap/cache/`

(غالبًا `755` للمجلدات و`644` للملفات؛ إن ظهرت أخطاء في السجلات جرّب صلاحيات `storage` و`bootstrap/cache` كما يوصي مزود الاستضافة.)

---

## 7) ربط تطبيق Flutter (مجتمع الطالب)

التطبيق يبني عنوان الـ API من أصل السيرفر + `/api/v1/`. راجع `lib/core/api/api_config.dart` و`lib/config/web_urls.dart`.

عند البناء للإنتاج، عرّف عنوان السيرفر (الدومين الفرعي **بدون** `/api/v1` في `WEB_BASE_URL`):

```text
--dart-define=WEB_BASE_URL=https://api.yourdomain.com
```

أو إن أردت تحديد جذر الـ API صراحةً:

```text
--dart-define=API_BASE_URL=https://api.yourdomain.com/api/v1/
```

(مع `/` في النهاية كما يفضّل الكود لتجنب أخطاء الدمج.)

---

## 8) تحقق سريع بعد الرفع

1. افتح في المتصفح: `https://api.yourdomain.com/api/v1/health`  
   يجب أن ترى JSON فيه `"status":"ok"`.
2. جرّب مسارًا يحتاج تسجيل دخول من التطبيق أو Postman حسب حاجتك.

---

## 9) ملاحظة عن «نسختين» من نفس المشروع

إذا كان **الموقع الرئيسي** يعمل من `public_html` والـ API من مجلد ثانٍ (`public_html/api`)، فلديك **نسختان من الكود**. أي تحديث (إصلاحات، migrations) يجب أن يُطبَّق على النسخة التي يخدمها الدومين الفرعي، أو توحّد النشر لاحقًا بحيث يشير الدومين الفرعي والموقع الرئيسي إلى **نفس** مجلد `public` إن كان ذلك مدعومًا في خطتك.

---

## ملخص في سطرين

1. اجعل جذر الدومين الفرعي = **`مجلد-المشروع/public`**.  
2. عدّل **`APP_URL`** وقاعدة البيانات في **`.env`**، شغّل **`composer`** و**`migrate`** و**`config:cache`**، ثم اختبر **`/api/v1/health`**.
