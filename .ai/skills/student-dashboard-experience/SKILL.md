# Student Dashboard Experience

This is NOT a UI generation skill.

This is a Product Design Intelligence Skill.

The objective is to build one of the world's best learning experiences inspired by modern SaaS products, premium operating systems, behavioral psychology, educational science and gamification.

Read this skill fully before designing or implementing any Student Dashboard screen.

For tokens and scales, see [design-system.md](design-system.md).
For rejection criteria and anti-patterns, see [anti-patterns.md](anti-patterns.md).
For AI + gamification surface map, see [experience-map.md](experience-map.md).

Suite companions (load as needed): `design-system`, `branding`, `dashboard-experience`, `gamification`, `ai-learning`, `motion-system`, `accessibility`, `arabic-typography`, `design-review`, `product-psychology`, `ux-research`, `interaction-design`, `analytics-visualization`, `learning-journey`.

## When to apply

Apply whenever the task touches:

- Student dashboard / home / portal
- Student learning experience redesign
- Student RTL layouts, components, or motion
- Embedded AI coach / missions / recommendations on student surfaces
- Student gamification (streak, XP, mastery, journey)

## Agent workflow

Copy and track:

```
Student Dashboard Experience Progress:
- [ ] 1. Map existing student dashboard routes, views, data, and constraints
- [ ] 2. Define the single question each section must answer
- [ ] 3. Pass internal quality gates (reject AI-looking / template-looking work)
- [ ] 4. Design RTL-first composition using Mindlytics tokens only
- [ ] 5. Embed AI + premium gamification as proactive product surfaces
- [ ] 6. Specify micro-interactions, empty states, skeletons, motion
- [ ] 7. Implement with reusable components + design tokens
- [ ] 8. Re-run quality gates on the final screen
```

### Step 1 — Map reality

Inspect the current Mindlytics student dashboard stack (routes, blades/components, controllers, services, existing data). Prefer extending real product data over inventing fake widgets.

### Step 2 — One question per section

Every section must answer exactly one of:

- What should I do now?
- What have I achieved?
- What is my next goal?
- Where am I progressing?
- How can AI help me?

If a block answers none, remove or redesign it.

### Step 3 — Quality gates (mandatory)

Before generating any design ask internally:

Does this look AI generated?

If YES

Reject it.

Does this look like a dashboard template?

Reject it.

Can someone identify this as generated by AI?

Reject it.

Is this memorable?

If NO

Redesign it.

Every generated screen must be original.

Also reject anything listed in [anti-patterns.md](anti-patterns.md).

## Final objective

Create a learning operating system.

Not a dashboard.

Students should enjoy opening the platform every day.

The experience should increase engagement, retention, completion rate and emotional connection with Mindlytics.

## Implementation rules for this repo

1. Preserve existing Mindlytics student auth, data models, and routes unless the task explicitly expands them.
2. Prefer Blade / existing frontend stack conventions already used by student surfaces.
3. Extract reusable partials/components; do not paste one-off mega templates.
4. Ship intentional motion (2–3 meaningful interactions minimum per major screen).
5. Every new screen must pass the quality gates again after implementation.
